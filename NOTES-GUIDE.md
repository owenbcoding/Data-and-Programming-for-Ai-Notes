# How to Take Notes in Markdown (for this course)

Use this format for every Codecademy subsection so your notes stay short, searchable, and useful.

---

## 1) One-page lesson template

Copy/paste this for each lesson:

```md
## <Lesson Name>

### Why this matters
- 1-2 lines on where this appears in ML/data work.

### Key ideas
- Idea 1:
- Idea 2:
- Idea 3:

### Syntax / formulas / commands
```python
# minimal working snippet
```

### Worked example
- Input:
- Steps:
- Output:

### Mistakes I made
- Mistake:
- Why it happened:
- Fix:

### Quick checks
- [ ] Can I explain this in plain English?
- [ ] Can I solve a small problem without looking?
- [ ] Can I spot when to use this in a project?

### Next review date
- YYYY-MM-DD
```

---

## 2) Rules that keep notes high quality

- Write for future-you: short bullets, not long paragraphs.
- Keep one concept per bullet.
- Always include one tiny runnable code example.
- Always capture at least one mistake and fix.
- Add links to related files in this repo (`03-...`, `06-...`, etc.).

---

## 3) Suggested weekly review loop

- End of each study day: add 3-5 bullets per lesson.
- End of week: summarize each module in 10 lines max.
- Before moving to next module: do one mini exercise from memory.

---

## 4) File naming convention (recommended)

- Keep module files as they are (`02-...`, `03-...`).
- Optionally add lesson-level files in a folder:
  - `notes/03-part1/01-syntax.md`
  - `notes/03-part1/02-functions.md`
  - `notes/03-part1/03-control-flow.md`

This keeps module summaries clean while allowing deep notes per lesson.
